# Motif-Based Classification of Rice Drought Response

This project predicts **Gene Regulation** (up- vs. down-regulation under drought) in
rice from promoter-sequence **cis-regulatory motifs**, together with the biological
condition (Variety, Tissue, Stage). Motifs are counted **globally** across each
promoter (no positional bins), combined with sequence-level statistics, and fed to a
family of hybrid deep-learning classifiers.

It contains two parallel experiments:

1. **Global (all varieties)** — train on the full dataset using all rice varieties.
2. **Top-K** — repeat the pipeline for the top-1 … top-13 varieties (by sample count)
   to find how many varieties give the best performance, then compare.

## 3. Input data

Both pipelines read a pre-merged RiceMetaSys drought CSV that must contain at least:
`promoter_sequence`, `Variety`, `Tissue`, `Stage`, and `Gene Regulation`.

- Global pipeline → `.../data_preprocess/RiceMetaSys_Drought_merged_all_excels_6.csv`
- Top-K pipeline  → `.../data_preprocess/RiceMetaSys_Drought_merged_all_excels_5.csv`

These paths are set as `INPUT_FILE` near the top of each pipeline script. **Update them
if your data lives elsewhere.** All other input/output paths are also hard-coded as
absolute paths at the top of each script — adjust them to your environment before running.

## 4. How to run

### A) Global experiment (all varieties)

```bash
cd "/home/saiful/DeepRice_Task1/motif_based_classification_ALL_DATA/MSc_thesis2"

# Step 1 — feature engineering: scans promoters for ~54 motifs, adds sequence stats,
# one-hot encodes conditions, and writes a stratified 80/10/10 split.
python rice_motif_pipeline_global.py

# Step 2 — train & evaluate all hybrid models on the generated split.
python rice_hybrid_classifier_global_v2.py
```

Step 1 writes `train.csv`, `dev.csv`, `test.csv`, and `feature_names.txt` to
`global motif counting based/output_global_data/`.
Step 2 writes trained models, metrics, and figures to
`global motif counting based/output_global/hybrid_models_v2_hierarchical_focal/`.

> Note: `rice_hybrid_classifier_global_v2.py` pins the GPU via
> `os.environ["CUDA_VISIBLE_DEVICES"] = "2"` and redirects stdout to
> `console_output_hybrid_classifier_global_v2`. Edit those lines if you want a
> different GPU or to print to the terminal.

### B) Top-K experiment (sweep over number of varieties)

Run everything (top-1 → top-13, then comparison) with the driver script:

```bash
cd "global motif counting based/all_top_k"
chmod +x run_topk_pipeline.sh
./run_topk_pipeline.sh            # all k = 1..13
# or a subset:
./run_topk_pipeline.sh 1 5 10 13
```

To run a single configuration manually:

```bash
cd "global motif counting based/all_top_k"
python rice_motif_pipeline_topk.py --top_k 8
python rice_hybrid_classifier_topk.py --top_k 8 --gpu 2
python compare_topk_results.py    # aggregate across all completed k
```

Per-k outputs land in `all_top_k/top{k}/{data,results}/`; logs in `all_top_k/logs/`;
the cross-k comparison report and figures in `all_top_k/comparison_results/`.

> Note: edit `GPU_ID` and `MAX_VARIETIES` at the top of `run_topk_pipeline.sh` to
> match your machine.

## 5. Models

Each classifier trains and compares a family of hybrid architectures that process the
motif feature vector as a sequence and fuse it with condition embeddings
(Variety / Tissue / Stage):

`HybridMLP`, `HybridLSTM`, `HybridTransformer`, `HybridCNNAttention`,
`HybridGatedFusion`, `HybridMultiScaleCNN`.

Training uses a custom **HierarchicalFocalLoss** (focal loss + class-imbalance alpha +
condition-rarity weighting), which was the best-performing loss in earlier experiments.

---

## 6. Results summary

From `all_top_k/comparison_results/comparison_report.txt`, the best configuration was
**Top-12 varieties with HybridLSTM** (44,896 samples): Test ROC-AUC **0.7825**,
F1 **0.7222**, MCC **0.4009**. Performance generally improved as more varieties (and
thus more training samples) were included.

3. Run the classifier script to train, evaluate, and export metrics + figures.
4. For the Top-K study, use `run_topk_pipeline.sh` and inspect `comparison_results/`.
